\section{目的}
本実験では，これまでの実験により得られた知識を生かしてALUの設計を行い
Gowin社製 GW1NR-9上にVerilogHDLで回路を構築する．
そして，構築した回路についてテストベンチを行い，正常に動作をしているかについて確認する．
また，追加機能としてプログラムカウンタやプログラムROM，また入力/出力機能を搭載したCPUの構築を行う．
さらに追加機能として，コンパイラの実装を行い，疑似C言語で記述したプログラムを
アセンブリに変換し，そのアセンブリから機械語に変換することで，CPU上で動作させる．
\section{原理}
本実験で構築するALU,CPUについて使用する原理について説明を行う．
\subsection{ALU}
ALUは算術論理演算装置と呼ばれるもので，CPUの中核をなす部分である．
入力された任意のビット幅の信号に対して，演算を行い出力する装置であり，
加算や減算，論理積や論理和などの演算を行うことができる．
本実験では，16bit幅の演算を行うALUを構築すする．
また，ALUの入力と出力においては，入力にA,B，出力に全部の演算結果を出し，ALUの前段と後段にALU用のセレクタを配置している．
これにより，ALUの設計とマルチプレクサの設計を分け，デバッグを行いやすくする．
\subsection{CPU}
CPUは中央処理装置と呼ばれるもので，コンピュータの中核をなす部分である．
入力された命令に対して，演算を行い出力する装置であり，ALUやメモリ，プログラムカウンタ(PC)や
プログラムROMなどの構成要素からなる．
本実験では，ALUに加えて，メモリやPC，プログラムROMを搭載したCPUを構築する．
CPUの入力にクロック信号を入力し，クロックに合わせて演算結果の書き込みを行っている．
\subsection{インストラクション}
インストラクションはCPUが理解できる命令である．
オペコードと呼ばれる命令の種類を表すビット列と，オペランドと呼ばれる引数を表すビット列から構成される．
本実験では，オペコードを6bit，オペランドを10bitとすることで，16bit幅の命令を構成する．
\subsection{オペコード}
オペコードは命令の種類を表すビット列であり，CPUが理解できる命令の種類を表すものである．
オペコードはCPUごとに異なり，CPUが理解できる命令の種類を表すものであり，
命令セットアーキテクチャとして定義される．
本実験では，ALUの演算の種類を表すオペコードを28種類定義した．
\subsection{オペランド}
オペランドは命令の引数を表すビット列であり，オペコードにより，何を表すかが変わる．
例えばADDI命令では，オペランドはACCに足す即値を表し，
ADDM命令では，オペランドはメモリの番号を表す．
また，特殊命令としてjmp命令では，オペランドはジャンプ先のアドレスを表す．
\subsection{手動/自動モード}
本実験では追加機能との棲み分けとして，モード切替を行うことが出来るようになっている．
手動モードでは，SW0 $\sim$ SW14とS2をインストラクションの入力とし，SW17をクロック源としている．
そして，外部からの入力を受け付けず，またjmpなどの命令も使用できない．
自動モードでは内部のプログラムROMに格納された命令を自動実行するモードであり，内部の27$[M\text{Hz}]$のクロックを使用している．
\subsection{入力/出力}
外部に接続しているポートを，内部のメモリと接続することにより，メモリの値を読むことにより，外部からの入力，
またメモリに値を書き込むことにより外部への値の出力を可能にしている．
これにより，CPUとポートを介してデータのやり取りができる．
本実験では，自動モードの際にこの機能を使用できるようになっている．
0番地にSW0 $\sim$ SW14とS2を接続し
1番地にLED0 $\sim$ LED6を接続，また2番地に7セグメント表示モジュールを接続させている．
これにより，2番地に値を書き込むと書き込んだ値が7セグメントLEDに4 bit * 4桁(16bit,16進数4桁)で表示される．
\subsection{アセンブリ}
アセンブリは機械語と一対一で対応する低水準言語である．
機械語はCPUが直接理解できる命令であるが，人間にとっては理解しづらいものである．
そのため，疑似C言語で記述したプログラムからアセンブリに変換を行うコンパイラの構築を行った．
\subsection{コンパイラ}
コンパイラは高水準言語で記述されたプログラムを低水準言語に変換するプログラムである．
高水準言語は人間にとって理解しやすいものであるが，CPUが直接理解できるものではない．
そして，if文やwhile文を実装するために，CMP命令群によるフラグ管理を実装し，条件分岐命令を実装した．
これによりある程度複雑な命令も実行できるようになっている．
本実験では例としてuint16\underline{~}t型の配列変数を用いた64bit幅のフィボナッチ数列を出力するプログラムを構築し，
また入出力機能を使用して実際に動作することを確認する．

\subsection{作成した回路の操作方法}
レポート内で度々モード切替などが出ているが，情報が統合されていないため，本章で情報の統合を行う．
\subsection{自動モード}
自動モードでは，内蔵されているプログラムがCPUにより順次内部クロックにより動作する．
内部のプログラムではスイッチとボタンによる入力をメモリのアドレスを読むことにより実装している．
そのため今回実装したフィボナッチ数列を求めるプログラムではスイッチ入力機能のテストを兼ねて，
スイッチの値を読んでいる．数を求めるとwhile文に入り，このwhile文の終了判定では，SW1の入力が切り替わったら終了するようになっている．
そのため，SW1の値を切り替えるごとに次のフィボナッチ数列の数を求めてくれる．そして，プログラム内で指定した回数に達した場合か，スイッチが変化してないタイミングではSW2とSW3の値により，
フィボナッチ数列を求めている配列のインデックスが指定できるようになっており，インデックスを変化させるとそれに応じた中身がMEM[2]に書き込まれる．MEM[2]はSevenSegmentと接続しているため，
そのまま配列の中身が16進数で表示される．
\subsection{手動モード}
手動モードでは，SW17をクロックとして命令を入力することができる．
SW17をクロックとして命令を入力するためには，SW15を1にする必要がある．
SW15を1にすることにより，命令入力マルチプレクサがプログラムROMからの命令入力からSWからの命令入力に切り替わる．
SWからの命令入力は，S2を15bit，S14~0を命令の14~0bitとする命令入力である．
また，このときの7セグメントLEDは課題の要件通りの動作になっており，ACCの内容を表示しているときにのみ，CPU内部の6種類のレジスタの値をLED出力で確認することが出来る．
この6種類のフラグは，COM命令群で使用する3つのレジスタと，オーバーフロー/キャリー,ゼロフラグである．

疑似C言語のソースファイルをアセンブリに変換するコンパイラをPythonで実装した．
コンパイラのプログラムをリスト\ref{code:compiler}に示す．また，ASMを機械語に変換するプログラムをリスト\ref{code:asm2bin}に示す．
本CPUは命令語長が16bitであり，命令は「オペコード6bit＋オペランド10bit（即値またはメモリアドレス）」で構成される．そのため，C$\rightarrow$ASM変換では，最終的に10bit範囲に収まる即値・アドレスを生成し，分岐命令はラベルを用いて記述できる形式のアセンブリを出力する．


\subsubsection{前処理（簡易プリプロセス）}
完全なCプリプロセッサではないが，本実験に必要な範囲で前処理を行い，後段の解析を簡単化している．主な処理は以下の通りである．
\begin{itemize}
    \item \texttt{\#include "..."}：ソースファイルのディレクトリを基準としてローカルヘッダを展開する．
    \item \texttt{\#define}（数値定数）：\texttt{0x..}，\texttt{0b..}，10進数の数値マクロを読み取り，定数として扱う．
    \item \texttt{\#pragma mem}：識別子とメモリアドレスの対応（メモリマップ）を固定できる．右辺は数値または\texttt{\#define}マクロ名を許可する．
    \item コメント除去：\texttt{//} および \texttt{/* */} を除去する．
    \item \texttt{struct} の簡易展開：\texttt{struct T \{ a; b; \};} と \texttt{struct T var;} を解析し，\texttt{var.a} を \texttt{var\_\_a} のような識別子に置換する．フィールドは連続アドレスに割り当てる．
    \item \texttt{malloc(N)}：\texttt{N} が整数リテラルのとき，コンパイル時に連続領域を確保し，呼び出しを先頭アドレスの数値へ置換する．
    \item \texttt{main()} 抽出：\texttt{main()} が存在する場合，\texttt{\{...\}} 内のみを抽出してコンパイル対象とする．
\end{itemize}

\subsubsection{メモリ割当（メモリマップ＋自動割当）}
本CPUはレジスタ数が限られ，変数は主にメモリへ\texttt{LOAD/STORE}することで扱う．よってコンパイル時に「識別子$\rightarrow$番地」の割当が必要となる．本実装では，ユーザ指定と自動割当を併用している．
\begin{itemize}
    \item ユーザ指定：\texttt{--map}で与えるJSON，または\texttt{\#pragma mem}で固定番地を指定する．
    \item 自動割当：ソース中に現れる変数名・配列名を走査し，未割当のものへ空き番地を割り当てる．配列は「観測された最大の定数添字$+1$」を長さとし，連続領域を確保する．
    \item 予約番地の保護：入出力に用いる番地など，システム予約領域へ一般変数が割り当てられないよう検査を行う．
\end{itemize}
